# 性能监控

## 启动追踪
当 VSCode 以 --trace 参数启动时，在 src/main.ts 中通过 contentTracing.startRecording(traceOptions) 开始记录追踪数据
追踪选项可以通过 --trace-category-filter 和 --trace-options 参数自定义

这里如果传入trace参数，在onReady启动之前会调用chromium的收集跟踪数据， 提供的底层的追踪工具允许我们深度了解 V8 的解析以及其他时间消耗情况，

一旦收到可以开始记录的请求，记录将会立马启动并且在子进程是异步记录听的. 当所有的子进程都收到 startRecording 请求的时候，callback 将会被调用.

categoryFilter是一个过滤器，它用来控制那些分类组应该被用来查找.过滤器应当有一个可选的 - 前缀来排除匹配的分类组.不允许同一个列表既是包含又是排斥.
```ts
app.once('ready', function () {
	// 如果指定了 trace 参数，则开始跟踪， 性能分析
	if (args['trace']) {
		let traceOptions: Electron.TraceConfig | Electron.TraceCategoriesAndOptions;
		if (args['trace-memory-infra']) {
			const customCategories = args['trace-category-filter']?.split(',') || [];
			customCategories.push('disabled-by-default-memory-infra', 'disabled-by-default-memory-infra.v8.code_stats');
			traceOptions = {
				included_categories: customCategories,
				excluded_categories: ['*'],
				memory_dump_config: {
					allowed_dump_modes: ['light', 'detailed'],
					triggers: [
						{
							type: 'periodic_interval',
							mode: 'detailed',
							min_time_between_dumps_ms: 10000
						},
						{
							type: 'periodic_interval',
							mode: 'light',
							min_time_between_dumps_ms: 1000
						}
					]
				}
			};
		} else {
			traceOptions = {
				categoryFilter: args['trace-category-filter'] || '*',
				traceOptions: args['trace-options'] || 'record-until-full,enable-sampling'
			};
		}

		contentTracing.startRecording(traceOptions).finally(() => onReady());
	} else {
		// 初始入口
		onReady();
	}
});
```
## 结束追踪
在窗口成功启动之后，vscode结束了性能问题的追踪（如果30秒窗口还没启动，那么也会结束性能问题的追踪）
stopTracing 方法是 Electron 的 contentTracing API 的一部分，在 VSCode 中主要通过以下路径被调用：
- 通过命令面板（F1）执行 workbench.action.stopTracing 命令
- 这个命令在 `src/vs/workbench/contrib/issue/electron-sandbox/process.contribution.ts` 中定义为 `StopTracing` 类
- 这个命令执行时会调用 `processService.stopTracing()`，即 `IProcessMainService` 接口中的 `stopTracing` 方法
最终实现在 `src/vs/platform/process/electron-main/processMainService.ts` 中的 `ProcessMainService` 类
执行过程：
- 如果 VSCode 不是以 --trace 参数启动的，则会显示对话框提示用户需要使用 --trace 参数重启 VSCode
- 如果用户确认，则会使用 --trace 参数重启应用
- 如果 VSCode 已经以 --trace 参数启动，执行 stopTracing 方法会：
  - 调用 Electron 的 contentTracing.stopRecording() 生成一个跟踪文件
  - 显示一个对话框，通知用户跟踪文件已创建
  - 在文件资源管理器中显示该文件
使用场景：
- 性能分析：跟踪应用程序的性能瓶颈和慢操作
- 调试：帮助开发人员理解应用程序的行为和执行路径
- 问题报告：生成跟踪文件以帮助开发人员诊断问题
contentTracing 是 Electron 提供的一个 API，用于收集 Chromium 内容模块生成的跟踪数据，帮助寻找性能瓶颈和慢操作。生成的跟踪文件可以在 Chrome 浏览器的 chrome://tracing 页面查看。这对于 VSCode 开发团队和高级用户诊断性能问题非常有用。
