# 进程通讯

VSCode 采用了多进程架构，通过不同进程之间的通信实现高性能、高可靠性的编辑器体验。

## 多进程架构概述

VSCode 基于 Electron 框架，采用了以下进程模型：

1. **主进程 (Main Process)**：负责应用程序生命周期管理、窗口创建、菜单处理等
2. **渲染进程 (Renderer Process)**：负责 UI 渲染和用户交互，包含工作台 (Workbench) 的主要界面
3. **扩展主机进程 (Extension Host Process)**：隔离运行扩展，防止影响主界面性能和稳定性
4. **共享进程 (Shared Process)**：处理多窗口间共享的任务，如扩展管理、搜索等
5. **辅助进程 (Utility Process)**：专门执行特定任务的进程，如调试、终端等
6. **语言服务进程 (Language Server Process)**：运行语言服务器协议（LSP）实现，如 TypeScript/JavaScript、Python、C++ 等的智能补全、诊断等。

## 进程间通信 (IPC) 机制

VSCode 的 IPC 系统主要基于以下几种机制：

### 主进程

`src/vs/code/electron-main/main.ts`
main.ts在启动应用后就创建了一个主进程 main process，它可以通过electron中的一些模块直接与原生GUI交互。

```ts
// main.ts在启动应用后就创建了一个主进程 main process，它可以通过electron中的一些模块直接与原生GUI交互。
mainProcessNodeIpcServer = await nodeIPCServe(environmentMainService.mainIPCHandle); // 创建服务端 ipc 服务（IPC 通常指 Inter-Process Communication，即进程间通信）
Event.once(lifecycleMainService.onWillShutdown)(() => mainProcessNodeIpcServer.dispose());
```

### 渲染进程

 VSCode 桌面版的渲染进程入口文件。这个文件扮演着非常重要的角色，它负责了整个 VSCode 的启动过程，包括了主进程的初始化、渲染进程的创建、扩展主机的启动等。
`src/vs/workbench/electron-sandbox/desktop.main.ts`
与 processExplorer.ts 不同，desktop.main.ts 是主工作台窗口的核心，而不是一个辅助工具窗口。它是用户与 VSCode 交互的主界面入口点。

#### 主进程与渲染进程之间的通信 Electron IPC

通过 Electron 的 `ipcMain` 和 `ipcRenderer` 模块实现主进程与渲染进程间的通信：
`ipcMain` 模块和 `ipcRenderer` 是类 `EventEmitter` 的实例

```ts
// 在渲染进程中
ipcRenderer.send('vscode:hello');
const onMessage = Event.fromNodeEventEmitter<VSBuffer>(ipcRenderer, 'vscode:message', (_, message) => VSBuffer.wrap(message));
```

在主进程中使用ipcMain接收渲染线程发送过来的异步或同步消息，发送过来的消息将触发事件。

在渲染进程中使用`ipcRenderer`向主进程发送同步或异步消息，也可以接收到主进程的消息。

- 发送消息，事件名为 `channel` .
- 回应同步消息, 你可以设置 `event.returnValue` .
- 回应异步消息, 你可以使用 `event.sender.send(...)`
创建IPC服务 `src/vs/base/parts/ipc/node/ipc.net.ts`

这里返回一个promise对象，成功则createServer

```ts
export function serve(hook: any): Promise<Server> {
	return new Promise<Server>((c, e) => {
		const server = createServer();

		server.on('error', e);
		server.listen(hook, () => {
			server.removeListener('error', e);
			c(new Server(server));
		});
	});
}
```

### 2. MessagePort 通信

使用 HTML5 的 MessagePort API 实现高性能的进程间通信，特别是在渲染进程与扩展主机进程间：

```ts
// 在接收端
class Protocol implements IMessagePassingProtocol {
  readonly onMessage;

  constructor(private port: MessagePortMain) {
    this.onMessage = Event.fromNodeEventEmitter<VSBuffer>(this.port, 'message', (e: MessageEvent) => {
      if (e.data) {
        return VSBuffer.wrap(e.data);
      }
      return VSBuffer.alloc(0);
    });
    // 启动端口以确保消息流动
    port.start();
  }

  send(message: VSBuffer): void {
    this.port.postMessage(message.buffer);
  }
}
```

### 3. Node.js 子进程通信

使用 Node.js 的 `child_process` 模块创建和通信与子进程（如扩展主机进程）：

```ts
// 在父进程中
const child = fork(modulePath, args, forkOpts);
const onMessage = Event.fromNodeEventEmitter(this.child, 'message', msg => msg);
```

## 通信协议与消息序列化

VSCode 使用协议层抽象底层通信细节，实现**跨进程的服务调用和事件通知**：

### 1. 通道 (Channel) 机制

```ts
// startup
async startup(): Promise<void> {
	// 初始化通道
	appInstantiationService.invokeFunction(accessor => this.initChannels(accessor, mainProcessElectronServer, sharedProcessClient));
}

initChannels
```

每一个通道，内部实现两个方法 listen和call， 通过 Channel 抽象，实现类似 RPC 的远程服务调用：

```ts
// 定义通道接口
interface IChannel {
  call<T>(command: string, arg?: any): Promise<T>;
  listen<T>(event: string, arg?: any): Event<T>;
}

// 使用通道进行远程调用
const channel = client.getChannel('extensionService');
await channel.call('activateByEvent', { event: 'onCommand:workbench.action.showCommands' });
```

### 2. 消息序列化

使用二进制缓冲区 (VSBuffer) 作为通信基础，实现高效的消息传递：

```ts
// 序列化消息
const writer = new BufferWriter();
serialize(writer, data);
protocol.send(writer.buffer);

// 反序列化消息
const reader = new BufferReader(message);
const data = deserialize(reader);
```

## 进程间通信的应用场景

### 1. 共享进程 (Shared Process)

`src/vs/platform/sharedProcess/electron-main/sharedProcess.ts`
处理需要在所有窗口之间共享的服务：

```ts
// 在主进程中
private async onWindowConnection(e: IpcMainEvent, nonce: string, responseChannel: string): Promise<void> {
  // 等待共享进程准备就绪
  await this.whenReady();

  // 连接到共享进程
  const port = await this.connect(responseChannel);

  // 将端口发送回请求窗口
  e.sender.postMessage(responseChannel, nonce, [port]);
}
```

### 2. 主进程服务访问

从渲染进程访问主进程中的服务：

```ts
// 在渲染进程中
export class ElectronIPCMainProcessService extends Disposable implements IMainProcessService {
  private mainProcessConnection: IPCElectronClient;

  constructor(windowId: number) {
    super();
    this.mainProcessConnection = this._register(new IPCElectronClient(`window:${windowId}`));
  }

  getChannel(channelName: string): IChannel {
    return this.mainProcessConnection.getChannel(channelName);
  }
}
```

### 3. 扩展主机通信

与扩展主机进程进行通信，执行扩展代码：

```ts
// 激活扩展
async activateByEvent(activationEvent: string, activationKind?: ActivationKind): Promise<void> {
  // 通过 IPC 渠道向扩展主机发送激活消息
  await this.extensionHostConnection.getChannel('extensionService').call('activateByEvent', { event: activationEvent, kind: activationKind });
}
```

### LSP( Language Server Protocol)

LSP 是 Language Server Protocol 的缩写，是微软为了解决编辑器和语言工具集成问题而设计的协议。其核心思想是将语言服务与编辑器分离，通过标准化的协议通信。

LSP 定义了语言服务器和编辑器之间的通信接口，包括请求和响应的格式、消息的类型等。
LSP 采用客户端-服务器模式：

- 客户端：编辑器（如 VSCode）
- 服务器：语言服务器（如 TypeScript、JSON 服务器）
- 通信：通过 JSON-RPC 2.0 协议

LSP 的实现通常包括以下几个方面：

- 语言服务器：提供语言相关的服务，如代码分析、代码补全、代码诊断等。
- 语言服务器客户端：负责与编辑器进行通信，发送请求并接收响应。
- 编辑器：提供用户界面，如代码编辑器、IDE 等。
- 语言服务器协议：定义了语言服务器和编辑器之间的通信接口，包括请求和响应的格式、消息的类型等。
详细请看[5.1-LSP.md](./5.1-LSP.md)

## 性能与可靠性考虑

1. **序列化开销**：使用二进制序列化减少 JSON 序列化的开销
2. **消息队列**：实现消息缓冲和批处理，减少 IPC 调用次数
3. **错误处理**：处理进程崩溃和通信中断，实现自动重连和恢复机制
4. **安全边界**：确保各进程只能访问其所需的资源和 API

VSCode 的多进程架构和高效的进程间通信机制，是其能够提供流畅用户体验同时支持强大扩展生态系统的关键因素。
