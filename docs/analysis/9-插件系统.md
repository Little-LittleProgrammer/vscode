# 插件系统

VSCode 的插件系统是其最强大的特性之一，允许开发者通过扩展来增强编辑器功能，支持新语言，添加调试器等。

## 插件系统架构

VSCode 采用了一种隔离的扩展架构，将扩展运行在单独的进程中，确保稳定性和性能：

### 1. 扩展主机进程

扩展在独立的 Node.js 进程（称为扩展主机）中运行：

```ts
// 在 src/vs/workbench/services/extensions/node/extensionHostProcess.ts
const extensionHost = new ExtensionHostMain(
  connectionData.remoteAuthority,
  params.initData,
  connectionData.initialDataProvider,
  createMessagePassingProtocol(protocol),
  params.hostUtils
);

// 启动扩展主机
extensionHost.start();
```

### 2. 扩展类型

VSCode 支持两种主要类型的扩展：

```ts
export const enum ExtensionType {
  System,  // 内置扩展，随VSCode一起分发
  User     // 用户安装的扩展
}
```

### 3. 扩展描述符

每个扩展通过描述符（`package.json`）定义其元数据和功能贡献点：

```json
{
  "name": "example-extension",
  "displayName": "Example Extension",
  "version": "1.0.0",
  "publisher": "publisher-name",
  "engines": {
    "vscode": "^1.60.0"

  "activationEvents": [
    "onCommand:extension.helloWorld"

    "commands": [
      {
        "command": "extension.helloWorld",
        "title": "Hello World"
      }
    ],
    "languages": [...],
    "debuggers": [...],
    "views": [...]
```

### 2. 扩展激活

扩展根据激活事件按需激活，而不是全部一次性加载：

```ts
export class ExtensionService implements IExtensionService {
  // 根据激活事件激活扩展
  async activateByEvent(activationEvent: string, activationKind?: ActivationKind): Promise<void> {
    // 查找响应此激活事件的扩展
    const toActivate = this._getExtensionsToActivateByEvent(activationEvent);

    // 依次激活扩展
    for (const extension of toActivate) {
      await this._activateExtension(extension.id, activationKind);
    }
  }

  // 激活单个扩展
  private async _activateExtension(extensionId: ExtensionIdentifier, activationKind?: ActivationKind): Promise<void> {
    // 加载扩展模块
    const extensionModule = await this._loadExtensionModule(extensionId);

    // 调用扩展的激活函数
    const exports = await extensionModule.activate();

    // 存储扩展导出的 API
    this._extensionExports.set(extensionId, exports);
  }
}
```

## 扩展 API

VSCode 提供了丰富的 API 供扩展使用，这些 API 定义在 `vscode` 命名空间中：

### 1. API 结构

VSCode 扩展 API 主要分为以下几个部分：

- **命令 API**：注册和执行命令
- **窗口 API**：访问编辑器、状态栏等 UI 元素
- **工作区 API**：访问文件系统和工作区设置
- **语言 API**：提供语言功能如代码补全、定义跳转等
- **调试 API**：创建和控制调试会话
- **任务 API**：创建和执行任务

### 2. API 实现示例

以命令 API 为例，展示其在 VSCode 中的实现：

```ts
// 在 src/vs/workbench/api/common/extHostCommands.ts
export class ExtHostCommands implements IExtHostCommands {
  // 注册命令
  registerCommand(id: string, callback: (...args: any[]) => any, thisArg?: any): Disposable {
    // 验证命令 ID
    if (!id.trim().length) {
      throw new Error('Invalid command id');
    }

    // 注册命令处理函数
    this._commands.set(id, { callback, thisArg, source: CallbackSource.Explicit });

    // 通知主进程有新命令注册
    this._proxy.$registerCommand(id);

    // 返回用于取消注册的 Disposable
    return new Disposable(() => {
      this._commands.delete(id);
      this._proxy.$unregisterCommand(id);
    });
  }

  // 执行命令
  executeCommand<T>(id: string, ...args: any[]): Promise<T> {
    // 检查命令是否在扩展主机已注册
    if (this._commands.has(id)) {
      // 本地执行命令
      return this._executeCommandLocal<T>(id, args);
    } else {
      // 通过主进程执行命令
      return this._proxy.$executeCommand<T>(id, args);
    }
  }
}
```

### 2. 贡献点处理

VSCode 会解析扩展的贡献点并应用到相应的服务：

```ts
export class ExtensionContributions {
  // 处理扩展的命令贡献
  static handleCommands(commands: ICommandContribution[], collector: IExtensionContributionCollector): void {
    if (!Array.isArray(commands)) {
      collector.error(localize('invalid.commands', "'commands' must be an array."));
      return;
    }

    for (const command of commands) {
      if (!command.command || typeof command.command !== 'string') {
        collector.error(localize('invalid.command', "Command must have a valid identifier."));
        continue;
      }

      if (!command.title || typeof command.title !== 'string') {
        collector.error(localize('invalid.title', "Command must have a valid title."));
        continue;
      }

      // 注册命令
      CommandsRegistry.registerCommand(command.command, () => {
        // 命令实际实现由扩展提供
      });
    }
  }
}
```
