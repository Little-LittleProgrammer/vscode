# 最最基础的流程

## 启动新窗口

### 文件路径

#### `main.ts`

1. `startup`

#### `/vs/code/electron-main/main.ts`

1. `startup`
   - 初始化服务， 将环境服务，用户数据，配置等等服务初始化，放到 `instantiationService` 中, 方便后续使用
   - 启动主实例
     - 从 `instantiationService` 中获取 日志、生命周期，文件等服务
     - 创建主实例， 进入 `vs/code/electron-main/app.ts` 的 `startup` 方法

#### `/vs/code/electron-main/app.ts`

1. `startup`
   1. 初始化共享进程
   2. 创建 app 实例服务
      - 将所有的服务放到 `appInstantiationService` 中, 方便后续使用
   3. 从 `appInstantiationService` 中来初始化：错误遥测、认证处理程序、瞬态配置文件处理程序、初始化通道,
   4. 主进程中建立与各个进程之间的通道 mainProcessNodeIpcServer.registerChannel
   5. 初始化 url 处理程序，主要用于判断是不是 vscode:// 协议启动的
   6. 打开窗口 `openFirstWindow`
2. `openFirstWindow`
   1. 获取 `windowsMainService` 服务
   2. 判断是不是 vscode:// 协议启动的
   3. 打开窗口 `windowsMainService.open` 执行 `src/vs/platform/windows/electron-main/windowsMainService.ts`

#### `src/vs/platform/windows/electron-main/windowsMainService.ts`

1. 执行 `open` 方法
2. 执行 `doOpen` 方法
3. 执行 `doOpenEmpty` 方法
4. 执行 `openInBrowserWindow` 方法, 实际创建或复用 Electron 窗口，并加载配置。
   - 窗口事件窗口监听，监听准备就绪事件，窗口关闭事件，窗口销毁事件，窗口最大化事件等等
5. 执行 `doOpenInBrowserWindow` 方法, 加载窗口配置并注册备份、配置文件等。
   - window.load()

#### `src/vs/platform/windows/electron-main/windowImpl.ts`

1. 执行 `load` 方法
   - loadURL `vs/code/electron-sandbox/workbench/workbench-dev.html`

#### `vs/code/electron-sandbox/workbench/workbench-dev.html`

#### `src/vs/code/electron-sandbox/workbench/workbench.ts`

加载工作台， 正式进入窗口创建流程

- `result.main(configuration)` 执行 `src/vs/workbench/workbench.desktop.main.ts`

#### `src/vs/workbench/electron-sandbox/desktop.main.ts`

1. 执行 `main` 方法
2. 执行 `DesktopMain.open` 方法
   - `Promise.all([初始化服务, DOM准备就绪])`
   - 初始化 `workbench` 服务
   - 执行 `workbench.startup`

#### `src/vs/workbench/browser/workbench.ts`

1. 先通过构造函数构建创建 `mainContainer`的 div 元素， 这个就是最终挂载的元素

2. 执行 `startup` 方法
   - 初始化 `workbench` 服务
   - 执行 `workbench.startup`
3. 执行`renderWorkbench`方法
   - 创建工作台的基础 DOM 结构和各个部件的容器元素
   - 初始化字体和样式设置（如字体抗锯齿处理）
   - 创建各个核心部件（如标题栏、活动栏、侧边栏、编辑器区域、面板、状态栏等）
   - 为每个部件创建 DOM 容器，并调用各部件的 create() 方法进行初始化
   - 创建通知处理程序，用于显示通知和消息
4. 执行 `createWorkbenchLayout` 挂载布局：创建工作台布局管理器
   - 初始化工作台的布局系统，创建 Grid 布局管理器
   - 定义各个部件在网格中的位置、大小和层级关系
   - 创建 SerializableGrid 实例，用于管理部件之间的布局关系
   - 设置部件的可见性、大小比例和初始状态
   - 处理部件之间的拖拽分隔线，允许用户调整各部件大小
   - 将网格布局结构（workbenchGrid.element）添加到 mainContainer 中
5. 执行 `layout` 应用布局计算
   - 计算工作台容器的实际尺寸（宽度和高度）
   - 设置 mainContainer 的位置和大小
   - 调用 workbenchGrid.layout() 方法，根据当前窗口尺寸计算并应用各部件的实际大小
   - 触发布局事件，通知各个部件进行内部布局调整
   - 设置 initialized 标志，表明工作台已完成初始化
   - 处理全屏模式、Zen 模式等特殊布局状态
6. 执行 `restore` 恢复工作台状态
   - 恢复用户之前的工作状态，包括打开的编辑器、视图和布局设置
   - 调用 restoreParts() 方法，恢复各个部件的状态
   - 恢复编辑器的内容、分组和布局
   - 恢复侧边栏、面板和辅助栏中的视图
   - 恢复 Zen 模式、编辑器居中模式等特殊状态
   - 处理布局的异步恢复操作，确保界面响应性
   - 完成后，将生命周期阶段设置为 "Restored"，然后延迟设置为 "Eventually"

至此编辑器窗口正式启动

## 打开文件夹或者工作区流程

### `src/vs/workbench/browser/actions/workspaceActions.ts`

1. 注册工作区操作事件: `AddRootFolderAction`, `RemoveRootFolderAction`, `OpenFileAction`, `OpenFolderAction`, `OpenFolderViaWorkspaceAction` 等等
2. 触发 `OpenWorkspaceAction。run` 事件
	- 执行弹窗 ` fileDialogService.pickWorkspaceAndOpen({ telemetryExtraData: data })`

> 举例 OpenFolderAction

### `src/vs/workbench/services/dialogs/browser/fileDialogService.ts`
1. 执行 `pickWorkspaceAndOpen`
	- 获取默认打开文件链接
	- 执行 `pickWorkspaceAndOpenSimplified` 方法
2. `pickWorkspaceAndOpenSimplified`
	- 执行 `pickResource` 方法 打开弹框
	- 通过主机服务，`IhostService` 打开窗口
