本文档解释了任务在VS Code中如何配置和执行。任务允许用户自动化外部操作，如构建、测试、打包或部署应用程序。本文涵盖了任务配置格式、任务如何被发现、解析和由任务系统执行。

有关任务系统架构的信息，请参阅核心服务和组件。

## 概述

VS Code的任务系统提供了一种将外部构建工具和进程集成到编辑器中的方式。任务在配置文件（`tasks.json`）中定义，由扩展贡献，或通过API以编程方式创建。任务系统负责解析这些配置、解析变量，并在终端或进程中执行命令。

任务系统支持不同的执行类型：

* Shell执行（在bash、PowerShell、cmd等shell中运行命令）
* 进程执行（直接进程生成）
* 自定义执行（扩展提供的任务执行）

## 任务配置

任务主要在`tasks.json`文件中配置，该文件可以存在于工作区或用户级别。配置格式遵循特定模式，定义任务属性，如命令、参数、问题匹配器和展示选项。

### 任务配置格式

`tasks.json`中的基本任务配置如下所示：

任务配置中的关键属性：

| 属性           | 描述                                       |
| -------------- | ------------------------------------------ |
| label          | 任务的显示名称                             |
| type           | 任务类型（shell、process或自定义类型）     |
| command        | 要执行的命令                               |
| args           | 传递给命令的参数                           |
| group          | 任务组（build、test等）及是否为默认任务    |
| problemMatcher | 用于检测任务输出中问题的模式               |
| presentation   | 任务终端如何呈现                           |
| dependsOn      | 此任务依赖的其他任务                       |
| options        | 命令选项，如工作目录和环境变量             |

### 任务类型和执行

VS Code支持三种主要的任务执行类型：

1. **Shell执行**：在bash、PowerShell或cmd等shell中运行命令
   * 支持shell特定功能，如管道、重定向
   * 可配置的shell选项和引用行为
2. **进程执行**：不通过shell直接生成进程
   * 对简单命令更高效
   * 无shell特定功能可用
3. **自定义执行**：扩展提供的任务执行
   * 允许扩展实现自定义任务执行逻辑
   * 用于特定构建系统或特定语言的任务

任务可以组织成代表常见操作的组：

## 任务解析和执行

当运行任务时，VS Code经历几个步骤来解析和执行它。

### 任务解析

任务解析涉及几个步骤：

1. **任务识别**：通过标签、类型或标识符查找任务
2. **变量解析**：解析任务配置中的变量
3. **依赖解析**：解析和执行任务依赖
4. **命令构建**：构建要执行的最终命令

任务服务维护来自各种来源（工作区、用户设置、扩展）的任务注册表，并在需要时解析它们。

来源：

* src/vs/workbench/contrib/tasks/browser/abstractTaskService.ts787-834
* src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts626-746

### 变量解析

任务支持在其配置中进行变量替换。变量被包含在`${...}`中，可以引用：

* 预定义变量，如`${workspaceFolder}`、`${file}`、`${fileBasename}`
* 环境变量
* 配置设置
* 提示用户的输入变量

变量解析过程：

1. 在任务配置中识别变量
2. 基于工作区上下文解析预定义变量
3. 如果需要，提示用户输入
4. 用解析后的值替换变量

来源：

* src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts83-109
* src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts662-745

### 任务依赖

任务可以使用`dependsOn`属性依赖其他任务。依赖可以通过以下方式指定：

* 任务标签
* 任务标识符对象

依赖可以并行或按顺序运行：

当执行具有依赖的任务时：

1. 任务系统识别所有依赖
2. 依赖按照指定顺序执行
3. 主任务在依赖完成后执行

## 终端任务系统

VS Code中的主要任务执行系统是终端任务系统，它在集成终端中执行任务。

终端任务系统：

1. 创建并管理用于任务执行的终端
2. 处理不同的执行类型（shell、process、custom）
3. 管理任务生命周期事件
4. 处理任务输出进行问题匹配
5. 处理任务终止和清理

来源：

* src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts143-219
* src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts273-307

### 终端创建和管理

在执行任务时，终端任务系统：

1. 基于配置创建新终端或重用现有终端
2. 使用适当的shell和选项配置终端
3. 为终端输出和退出设置事件监听器
4. 在终端中执行命令

系统基于任务配置管理终端重用：

| 面板选项      | 行为                              |
| ------------ | --------------------------------- |
| shared       | 在任务之间重用终端                |
| dedicated    | 为任务使用专用终端                |
| new          | 每次都创建新终端                  |

### 任务事件和生命周期

任务系统在整个任务生命周期中发出事件：

| 事件          | 描述                             |
| -------------- | --------------------------------- |
| start          | 任务已启动                       |
| active         | 任务正在活跃运行                 |
| processStarted | 任务进程已启动                   |
| processEnded   | 任务进程已结束                   |
| inactive       | 任务处于非活跃状态但未完成       |
| end            | 任务已完成                       |
| terminated     | 任务被终止                       |

这些事件用于更新UI、跟踪任务状态和触发依赖操作。

来源：

* src/vs/workbench/api/common/shared/tasks.ts54-93
* src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts433-441

### 问题匹配

终端任务系统包括分析任务输出以检测错误和警告的问题匹配器：

1. 从终端捕获任务输出
2. 问题匹配器使用正则表达式分析输出
3. 检测到的问题报告给问题面板
4. 问题链接到源文件以便导航

问题匹配器可以是：

* 监视型（持续监控输出）
* 开始/结束型（在特定模式之间活跃）
* 后台型（在后台运行）

## 自动任务执行

VS Code支持在某些场景下自动运行任务：

任务可以配置为自动运行：

1. **在文件夹打开时**：使用`runOn: folderOpen`属性
2. **作为依赖项**：当在另一个任务的`dependsOn`属性中指定时
3. **以编程方式**：通过VS Code API

`RunAutomaticTasks`组件负责检测和运行在文件夹打开时应自动执行的任务。

## 结论

VS Code的任务系统提供了一种灵活且强大的方式，将外部工具和进程集成到编辑器中。通过任务配置，用户可以定义命令如何执行、输出如何呈现以及如何检测问题。任务系统支持不同的执行类型，并为扩展提供API以贡献自定义任务功能。

了解任务配置和执行模型有助于用户有效地自动化其开发工作流程，并将外部工具集成到VS Code中。
