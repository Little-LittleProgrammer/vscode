VS Code 任务系统提供了一个框架，用于在编辑器内执行构建、测试和其他自动化任务。它允许用户从各种来源（包括工作区配置文件、扩展和用户设置）定义、配置和运行任务。

本文档涵盖了任务系统的核心架构、任务如何定义、解析和执行，以及该系统如何与终端服务等其他 VS Code 组件集成。

## 概述

任务系统使用户能够通过定义可以在 VS Code 中执行的任务来自动化常见的开发工作流程。任务可以被配置为运行 shell 命令、外部进程或由扩展提供的自定义执行逻辑。

## 任务服务架构

任务服务是任务系统的核心组件，负责管理任务定义、解析任务和执行任务。它实现了 `ITaskService` 接口，并作为其他 VS Code 组件与任务交互的入口点。

来源：

* src/vs/workbench/contrib/tasks/common/taskService.ts64-107
* src/vs/workbench/contrib/tasks/browser/abstractTaskService.ts189-195
* src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts143-146

### 任务服务实现

`AbstractTaskService` 类提供了任务服务的核心实现，特定平台的实现扩展了它：

1. `TaskService`（浏览器版）- 用于基于网络的 VS Code，仅支持基于终端的任务
2. `TaskService`（electron-sandbox）- 用于桌面 VS Code，同时支持基于终端和基于进程的任务

任务服务维护：

* 来自扩展的任务提供程序注册表
* 工作区任务的缓存
* 当前任务系统实现
* 运行任务的状态

## 任务定义

任务由其类型、属性和执行细节定义。任务系统支持几种类型的任务：

1. **贡献的任务** - 由扩展提供的任务
2. **自定义任务** - 用户在 tasks.json 中定义的任务
3. **配置任务** - 需要在执行前解析的任务

来源：

* src/vs/workbench/contrib/tasks/common/tasks.ts476-489
* src/vs/workbench/contrib/tasks/common/tasks.ts1000-1100
* src/vs/workbench/contrib/tasks/common/taskConfiguration.ts1000-1100

### 任务属性

任务具有各种定义其行为的属性：

| 属性            | 描述                                       |
| --------------- | ------------------------------------------ |
| type            | 任务类型（例如，"shell"、"process"、"npm"） |
| label           | 任务的显示名称                             |
| command         | 要执行的命令                               |
| args            | 命令的参数                                 |
| group           | 任务组（例如，"build"、"test"）            |
| presentation    | 终端呈现选项                               |
| problemMatchers | 用于检测错误的问题匹配器                   |
| dependsOn       | 此任务依赖的其他任务                       |
| isBackground    | 任务是否在后台运行                         |

## 任务执行

任务系统支持三种类型的任务执行：

1. **Shell 执行** - 在 shell 中运行命令（例如，bash、PowerShell）
2. **进程执行** - 直接运行外部进程
3. **自定义执行** - 允许扩展提供自定义执行逻辑

来源：

* src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts504-580

* src/vs/workbench/api/common/extHostTask.ts58-93

### 任务执行流程

执行任务时，会发生以下步骤：

1. 如果是配置任务，则解析任务
2. 如果任务有依赖项，则执行这些依赖项
3. 创建并跟踪任务执行
4. 根据任务类型调用适当的执行方法
5. 为任务创建或重用终端
6. 在终端中执行命令
7. 附加问题匹配器以检测错误
8. 随着任务进行，触发任务事件

### 终端任务系统

`TerminalTaskSystem` 类负责：

1. 为任务创建和管理终端实例
2. 在终端中执行任务
3. 跟踪活动和空闲的任务终端
4. 处理任务终止
5. 管理任务的问题匹配器

它维护几个数据结构：

* `_activeTasks`：当前运行任务的映射
* `_terminals`：用于任务的终端映射
* `_idleTaskTerminals`：可以为任务重用的终端映射

## 任务事件

任务系统在执行任务时触发事件，这些事件用于更新 UI 和通知扩展。主要事件有：

| 事件                        | 描述                 |
| --------------------------- | -------------------- |
| TaskEventKind.Start         | 任务已启动           |
| TaskEventKind.Active        | 任务正在活动运行     |
| TaskEventKind.Inactive      | 任务已暂停/等待      |
| TaskEventKind.End           | 任务已完成           |
| TaskEventKind.Terminated    | 任务被终止           |
| TaskEventKind.ProcessStarted | 任务进程已启动       |
| TaskEventKind.ProcessEnded  | 任务进程已结束       |

## 结论

VS Code 任务系统提供了一个灵活且可扩展的框架，用于在编辑器内执行任务。它支持各种任务类型、执行方法和配置选项，并与终端服务和问题匹配器系统等其他 VS Code 组件紧密集成。

任务系统的核心组件有：

1. **任务服务** - 管理任务定义、提供程序和执行
2. **终端任务系统** - 在终端中执行任务
3. **任务配置** - 解析和验证任务配置
4. **问题匹配器** - 检测任务输出中的错误和警告

扩展可以通过提供任务类型和任务提供程序来扩展任务系统，用户可以在 tasks.json 文件或通过 UI 配置任务。
